# Сетевое программное средство управления финансами проектов и анализа рисков в строительной компании («СтройФинРиск»)

Программный комплекс разработан на платформе **.NET 9.0 (C# 13 / ASP.NET Core 9 MVC / WPF / Entity Framework Core 9 / xUnit)** с хранением данных в **MS SQL Server** в соответствии с требованиями курсового проекта (`Наработка общ.docx`, гл. 1–2).

---

## 2. Подключение к MS SQL Server и логика инициализации БД

Клиентские приложения (`FinanveManager.Web` и `FinanveManager.WpfClient`) работают **только с реальным MS SQL Server** через `FinanveManager.Data`. Автоматического переключения на локальную память (`InMemory`) при отсутствии SQL Server нет (`InMemory` оставлен исключительно для изолированных модульных тестов `AppDatabaseFactory.CreateInMemoryForTests`).

### Где настраивается строка подключения
- Веб-клиент: `src/FinanveManager.Web/appsettings.json`
- WPF-клиент: `src/FinanveManager.WpfClient/appsettings.json`

По умолчанию указана строка:
```json
"ConnectionStrings": {
  "DefaultConnection": "Server=.;Database=FinanveManagerDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true"
}
```
Если на вашем компьютере используется именованный экземпляр или LocalDB, укажите его в `Server=`:
- SQL Server Express: `Server=.\SQLEXPRESS;Database=FinanveManagerDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true`
- Visual Studio LocalDB: `Server=(localdb)\mssqllocaldb;Database=FinanveManagerDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true`

### Как ведёт себя библиотека `FinanveManager.Data` при запуске (`DbInitializer.EnsureSqlServerDatabaseAsync`)
1. **Проверка соединения с сервером SQL Server (`master`)**:
   - Если сервер недоступен, служба остановлена или неверна строка подключения — метод выбрасывает явное исключение `InvalidOperationException` с указанием адреса сервера и причины ошибки (`MessageBox` в WPF или ошибка запуска в Web).
2. **Проверка существования базы данных (`SELECT DB_ID(@dbName)`)**:
   - Если база данных **`FinanveManagerDb` ещё не создана** — библиотека **создаёт базу данных пустой**: формируются схемы (`finance`, `risk`, `security`, `audit`), все 25 таблиц (включая `finance.ProjectAssignments`) и представление `finance.vFreeLimit`, **без автоматической вставки демонстрационных записей** (во всех таблицах `0` строк).
   - Если база данных была создана вручную заранее через `database/01_schemas_and_tables.sql` и `database/02_seed_data.sql` — система сразу работает с существующими таблицами и данными (при необходимости автоматически добавляя недостающую таблицу `finance.ProjectAssignments`).
3. **Первый вход в пустую базу данных**:
   - Если в таблице `security.Users` нет записей (`0` пользователей), на экране входа в Web и WPF появляется информационная карточка с двумя явными действиями (выполняются только по нажатию пользователя):
     - **«Создать 7 ролей (табл. 1.8), `admin` и `director` (`CEO`)»** — добавляет 7 ролей, администратора, руководителя организации и базовый справочник статей затрат (`ST-01`..`ST-04`) без демонстрационных проектов, чтобы сразу можно было завести сотрудников (`admin`) и создать проекты / назначить прорабов (`director`);
     - **«Загрузить контрольные примеры главы 1»** — загружает все 7 демо-учёток, проекты, назначения команд, договоры, бюджеты, заявки и 12 рисков (`R-01`..`R-12`).
   - В качестве альтернативы можно выполнить `database/02_seed_data.sql` напрямую в SSMS и обновить экран входа.

## 4. Реализованные алгоритмы и контрольные примеры (гл. 1)

1. **Контроль свободного лимита (витрина `finance.vFreeLimit`, без двойного списания):**
   $$L_{\text{дост}} = B - O, \qquad O_{\text{ост}} = O - F$$
   - Для проекта `PRJ-2026-01` / `ST-01`: $B = 10\,000$, $O = 6\,000$, $F = 3\,000$, заявки $Q = 1\,000 \Rightarrow L_{\text{дост}} = 4\,000$, $O_{\text{ост}} = 3\,000$.
   - Заявка с превышением лимита (`PRJ-2026-02` / `ST-02`, $L_{\text{дост}} = -500$) автоматически переходит в статус **`Blocked`** до согласования перерасхода руководителем организации (`UC04`).
2. **Расчёт суммы к оплате по акту С-2 / справке С-3:**
   $$S_{\text{к\_опл}} = S_{\text{акт}} - A_{\text{зач}} - U_{\text{удерж}}$$
3. **Прогноз стоимости по освоенному объёму (EVM):**
   - $CPI = EV / AC$, $SPI = EV / PV$, $EAC = AC + (BAC - EV)/CPI$.
   - Для `PRJ-2026-01`: $EV = 3\,000$, $AC = 3\,300$, $PV = 3\,400$, $BAC = 11\,000 \Rightarrow CPI \approx 0{,}909$, $SPI \approx 0{,}882$, $EAC = 12\,100$.
4. **Платёжный календарь и кассовые разрывы (5 / 30 / 90 дней):**
   $$C(t) = C(t-1) + P(t) - V(t), \qquad \text{Разрыв}(t) = \max(0,\ C_{\min} - C(t))$$
5. **Оценка рисков, матрица 5×5 и резерв P80 (`z = 0,84`, СТБ ISO 31000-2020):**
   $$EMV_i = p_i \cdot C_i, \qquad \sigma = \sqrt{\sum p_i (1 - p_i) C_i^2}, \qquad R_{P80} = \sum EMV_i + 0{,}84 \cdot \sigma$$
   - Для 12 рисков проекта `PRJ-2026-01`: $\sum EMV = 1\,340{,}00$, $\sigma = 723{,}22$, $R_{P80} = 1\,947{,}51$ тыс. р. (округлённо $1\,948$), остаточный $\sum EMV_{\text{ост}} = 715{,}00$ тыс. р.

## 5. Запуск и тестирование

### Запуск в Visual Studio 2022 (17.12+ с .NET 9 SDK)
1. Убедитесь, что **MS SQL Server** запущен, и при необходимости скорректируйте `ConnectionStrings:DefaultConnection` в `src/FinanveManager.Web/appsettings.json` и `src/FinanveManager.WpfClient/appsettings.json`.
2. *(По желанию)* Разверните структуру и примеры заранее через SSMS: выполните `database/01_schemas_and_tables.sql`, затем `database/02_seed_data.sql`. Если этого не делать, приложения сами создадут пустую БД `FinanveManagerDb` при первом запуске и предложат инициализацию на экране входа.
3. Откройте `Finanve_manager_and_risk_analyst.sln`:
   - для запуска **Веб-клиента** выберите стартовым проектом **`FinanveManager.Web`** и нажмите **F5** (`https://localhost:5051/Account/Login` или `http://localhost:5050/Account/Login`);
   - для запуска **Настольного клиента** выберите стартовым проектом **`FinanveManager.WpfClient`** и нажмите **F5**.

### Сборка и запуск тестов из командной строки
```bash
dotnet restore Finanve_manager_and_risk_analyst.sln
dotnet build Finanve_manager_and_risk_analyst.sln -c Release
dotnet test tests/FinanveManager.Tests/FinanveManager.Tests.csproj
```

> **Примечание по NuGet (`.NET 9.0`):** пакеты `Microsoft.EntityFrameworkCore.SqlServer` и `Microsoft.EntityFrameworkCore.InMemory` в `FinanveManager.Data.csproj` закреплены на версии **`9.0.0`** (совместимой с `net9.0`). Не повышайте их до `10.x`/`11.x` без миграции целевого фреймворка.
