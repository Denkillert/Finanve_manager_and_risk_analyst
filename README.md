## 2. Подключение к MS SQL Server и инициализация базы данных

Клиентские приложения (`FinanveManager.Web` и `FinanveManager.WpfClient`) работают **только с реальным MS SQL Server** через `FinanveManager.Data`. Автоматического отката в локальную память (`InMemory`) при недоступности SQL Server нет (`InMemory` используется только в изолированных модульных тестах `AppDatabaseFactory.CreateInMemoryForTests`).

### Где настраивается строка подключения
- Веб-клиент: `src/FinanveManager.Web/appsettings.json`
- WPF-клиент: `src/FinanveManager.WpfClient/appsettings.json`

Пример строки подключения:
```json
"ConnectionStrings": {
  "DefaultConnection": "Server=localhost;Database=FinanveManagerDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true"
}
```
Для именованных экземпляров измените `Server=`:
- SQL Server Express: `Server=.\SQLEXPRESS;Database=FinanveManagerDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true`
- Visual Studio LocalDB: `Server=(localdb)\mssqllocaldb;Database=FinanveManagerDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true`

### Поведение при запуске (`DbInitializer.EnsureSqlServerDatabaseAsync`)
1. **Проверка доступности SQL Server (`master`)**:
   - Если сервер недоступен или неверна строка подключения — приложение выбрасывает явное сообщение об ошибке подключения (`MessageBox` в WPF или ошибка запуска в Web).
2. **Создание пустой БД при отсутствии (`SELECT DB_ID(@dbName)`)**:
   - Если `FinanveManagerDb` отсутствует на сервере, создаётся **пустая база данных** со всеми схемами (`finance`, `risk`, `security`, `audit`), **25 таблицами** (включая `finance.ProjectAssignments`) и представлением `finance.vFreeLimit`, без автоматической вставки тестовых данных.
   - Если база данных уже создана заранее через `database/01_schemas_and_tables.sql` (и `02_seed_data.sql`), система использует её и при необходимости автоматически досоздаёт отсутствующую таблицу `finance.ProjectAssignments` / представление `finance.vFreeLimit`.
   - Если предыдущее создание пустой БД прервалось с неполной схемой (0 строк данных), система безопасно очищает незавершённую пустую БД и пересоздаёт структуру целиком.
3. **Первый запуск при пустой таблице `security.Users`**:
   - На экране входа (`LoginWindow` в WPF и `/Account/Login` в Web) отображается блок с двумя вариантами инициализации (срабатывают только по явному нажатию кнопки):
     1. **«Создать 7 ролей (табл. 1.8), admin и director (CEO)»** (`SeedRolesAndAdminOnlyAsync`) — минимальный старт без демонстрационных проектов: создаёт 7 стандартных ролей, администратора (`admin`), руководителя организации (`director`) и 4 базовые статьи затрат (`ST-01`..`ST-04`). После этого можно сразу работать с реальными проектами с нуля: под `admin` завести сотрудников (`pm`, `finmanager`, `accountant`, `supply`, `risk`), а под `director` создать первый проект и назначить прораба.
     2. **«Загрузить контрольные примеры главы 1»** (`SeedIfEmptyAsync`) — загружает полный демонстрационный набор: 7 учётных записей, 2 проекта (`PRJ-2026-01`, `PRJ-2026-02`), назначения команды, объекты, этапы, бюджеты, договоры, авансы, заявки, платежи и 12 рисков (`R-01`..`R-12`).

## 3. Разделение клиентов, вход в систему и безопасность

Согласно **таблице 1.8** и **НФТ-1 / НФТ-7 / НФТ-8**:
- Каждая роль привязана к строго определённому клиентскому приложению (**4 роли в WPF**, **3 роли в Web**). Попытка войти веб-ролью в WPF или WPF-ролью в Web отклоняется сервером авторизации с записью в аудит.
- Внутри каждого клиента настроена **жёсткая изоляция разделов и данных**: в меню и на формах отображаются только экраны и кнопки, относящиеся к задачам конкретной роли, а в Web-контроллерах доступ дополнительно защищён атрибутами `[Authorize(Roles = ...)]` (при переходе по прямой ссылке на чужой раздел возвращается `AccessDenied`).
- Пароли хранятся в виде `PBKDF2-SHA256` хэшей (минимальная длина пароля нового пользователя — 12 символов).
- После **5 подряд неудачных попыток входа** учётная запись блокируется на **15 минут** (снять блокировку раньше срока может `Admin`).
- Демонстрационный пароль для всех стартовых учётных записей: **`StroyFin2026!`** (для `admin` дополнительно обязателен код 2FA **`246810`**).

## 4. Подробное руководство по каждой из 7 ролей

### 4.1. Руководитель организации (`CEO` / `director`, WPF)

**Назначение роли:** стратегическое и портфельное управление строительной компанией, создание проектов и формирование их команд, утверждение бюджетов, разрешение или отклонение перерасхода (`UC04`), контроль ликвидности и совокупного резерва рисков P80.

#### Доступные разделы и управление

1. **«Главная панель»** (открывается при входе):
   - **5 карточек KPI:** контрактная цена портфеля, утверждённый бюджет $BAC$, свободный лимит $L_{\text{дост}}$, резерв рисков $P80$, статус кассовых разрывов на 90 дней.
   - **Таблица прогноза EVM + P80:** показатели $V, BAC, PV, EV, AC, CPI, SPI, EAC$, $P80$ и итоговый финансовый результат $R_{\text{фин}} = V - EAC - P80$ по каждому проекту.
   - **Блоки «Заявки, требующие решения»**, **«Ликвидность и кассовые разрывы»** и **«Уведомления и триггеры рисков»**.
   - **Что влияет:** все данные в этом разделе носят контрольно-аналитический характер и агрегируются автоматически на основании утверждённых бюджетов, этапов работ (`PV/EV/AC`), графика платежей и реестра рисков.

2. **«Проекты и бюджеты»**:
   - **Карточка «Создание нового проекта и назначение руководителя проекта (прораба)»:**
     - Поля: `Шифр проекта`, `Наименование проекта`, `Цена V (тыс. р.)`, `Валюта`, `Нач. остаток ДС`, `Мин. остаток ДС`, `Дата начала`, `Дата окончания`, `Первый объект строительства`, `Адрес объекта`, выпадающий список `Назначить руководителя (прораба)`.
     - Кнопка **«Создать проект и назначить прораба»**:
       - *Что делает и на что влияет:* создаёт новый `Project`, первый `ConstructionObject`, стартовую черновую версию бюджета `v1` со статусом **`Draft`** (если БД была абсолютно пустой — автоматически создаёт организацию, портфель и статьи затрат `ST-01`..`ST-04`), назначает выбранного прораба с флагом `IsPrimaryManager = true` в `finance.ProjectAssignments`, отправляет ему уведомление и сразу делает проект видимым этому прорабу в Веб-клиенте.
   - **Блок «Добавление объекта строительства и этапа работ (PV) к существующему проекту»:**
     - Поля: выбор проекта, наименование объекта, адрес, наименование этапа, `PV` этапа; кнопка **«Добавить объект / этап»**.
     - *Что делает и на что влияет:* добавляет новый объект строительства (на него потом можно распределять лимиты, договоры и акты) и этап работ с плановым объёмом $PV$ (входит в расчёт $SPI$ и прогноза EVM).
   - **Карточка «Команда проекта и закреплённые руководители (прорабы)»:**
     - Поля: выбор проекта, выбор активного сотрудника (кроме `Admin`), текстовая роль на проекте (по умолчанию `Руководитель проекта (прораб)`), флажок `Ответственный прораб / РП`.
     - Кнопки **«Назначить в проект»** и **«Снять выбранное назначение»**.
     - *Что делает и на что влияет:* напрямую определяет, **какие именно проекты, объекты, заявки и акты увидит `ProjectManager` в Веб-клиенте**. При установке флажка `Ответственный прораб / РП` статус основного руководителя по проекту автоматически переходит к новому назначенному сотруднику (прежний остаётся участником без флага основного прораба). Снятие назначения немедленно закрывает прорабу доступ к проекту.
   - **Карточки управления бюджетом:**
     - **«Создать Draft»** — создаёт следующую черновую версию бюджета (`v2`, `v3`…) для корректировки лимитов без изменения действующего утверждённого бюджета.
     - **«Добавить в Draft»** и **«Сохранить лимит»** — задаёт или изменяет сумму лимита по паре *(Объект × Статья затрат)* строго в черновой версии (`Draft`).
     - **«Утвердить выбранную Draft-версию»** — переводит черновую версию в статус **`Approved`**, а предыдущую утверждённую версию в **`Archived`**.
     - *На что влияет утверждение бюджета:* только после перехода версии в `Approved` её суммы попадают в $BAC$, в витрину `finance.vFreeLimit` как плановый бюджет $B$, и становятся доступны для проверки платёжных заявок. Без утверждённого бюджета любая заявка по статье упрётся в нулевой лимит $B = 0$.

3. **«Платёжные заявки»**:
   - Может создавать заявки (**«Создать и проверить»**), согласовывать обычные заявки (**«Согласовать (ЭЦП)»**), возвращать на доработку (**«Вернуть на доработку»**), а также принимать эксклюзивное для `CEO` решение по **сценарию `UC04`** для заявок в статусе **`Заблокирована`** (`Blocked`):
     - **«Согласовать перерасход (CEO)»** (с текстовым обоснованием) — переводит заблокированную заявку в статус `PendingApproval` (`ApprovedByManagement` → `PendingApproval`), разрешая дальнейшее согласование и оплату сверх лимита, и фиксирует персональную ответственность в журнале аудита.
     - **«Отклонить перерасход»** — окончательно переводит заявку в статус **`Отклонена`** (`Rejected`).
   - *Примечание:* кнопка исполнения платежа (`Accountant`) для `CEO` скрыта — разделение обязанностей не позволяет директору самостоятельно проводить банковские списания.

4. **«Платёжный календарь»**, **«Риски и резерв P80»**, **«Отчёты»**:
   - В календаре видит кассовые разрывы портфеля и при необходимости переносит даты плановых платежей (**«Перенести платёж»**).
   - В рисках видит матрицу 5×5, реестр рисков, резерв P80 и может добавлять/переоценивать риски.
   - В отчётах формирует все 5 регламентных отчётов и экспортирует в CSV.

### 4.2. Финансовый менеджер (`FinancialManager` / `finmanager`, Web)

**Назначение роли:** оперативное финансовое управление в Веб-клиенте — планирование бюджетов (`Draft`), контроль и акцепт (ЭЦП) платёжных заявок, балансировка платёжного календаря (устранение кассовых разрывов), контроль авансов и договоров.

**Что скрыто:** раздел **«Риски и резерв P80»**, карточка и колонка `Резерв P80` на главной панели, отчёт по рискам и блок импорта банковской выписки (принадлежит `Accountant`).

#### Доступные разделы и управление

1. **«Главная панель» (`/Dashboard`)**:
   - Финансовые KPI (контрактная цена, бюджет $BAC$, свободный лимит $L_{\text{дост}}$, кассовые разрывы на 90 дней), таблица EVM с маржой $(V - EAC)$, заявки, требующие решения, и уведомления (**«Прочитать все»**).

2. **«Проекты и бюджеты» (`/Projects`)**:
   - Просмотр назначенных команд (прорабов) и витрины `finance.vFreeLimit`.
   - **«Создать черновую версию (Draft)»**, **«Добавить / обновить лимит в Draft»**, **«Сохранить»** (для строк существующих `Draft`-лимитов).
   - *На что влияет:* готовит бюджеты к утверждению; до тех пор, пока `CEO` не нажмёт «Утвердить» в WPF, изменения в `Draft` не меняют действующий лимит $B$.

3. **«Платёжные заявки» (`/Requests`)**:
   - Создание заявок, но главное действие — финальное финансовое визирование заявок в статусе **`На согласовании`** (`PendingApproval`):
     - **«Согласовать (ЭЦП)»** — формирует отпечаток ЭЦП, переводит заявку в **`Согласована`** (`Approved`), **создаёт или увеличивает принятое обязательство $O$** в таблице `finance.Obligations`. *Важное влияние:* именно с этого момента уменьшается свободный лимит $L_{\text{дост}} = B - O$ и заявка появляется у Бухгалтера на оплату!
     - **«Вернуть»** — переводит заявку в `Returned` для исправления прорабом или снабженцем.
     - **«Отклонить»** — окончательно закрывает заявку как `Rejected`.
   - *Ограничение:* заблокированные из-за перерасхода заявки (`Blocked`) финансовый менеджер согласовать с ЭЦП **не может**, пока `CEO` не разрешит перерасход (`UC04`).

4. **«Платёжный календарь» (`/Calendar`)**:
   - Фильтр по проекту и горизонту (`5`, `30`, `90` дней), список просроченных поступлений от заказчика (> 10 дн.).
   - В таблице графика платежей поле новой даты и кнопка **«Перенести»**.
   - *На что влияет:* изменение `PlannedDate` сразу пересчитывает ежедневный остаток $C(t)$ и кассовые разрывы $\max(0, C_{\min} - C(t))$, позволяя сдвинуть расходную операцию за дату крупного поступления от заказчика и ликвидировать дефицит средств.

5. **«Договоры и выписки» (`/Contracts`)**:
   - **«Зарегистрировать договор»**, **«Зачесть»** (ручной зачёт выданного аванса: уменьшает $A_{\text{ост}}$ и при полном зачёте снимает просрочку аванса, разблокируя новые авансовые заявки по договору), **«Выполнить маппинг сметы»** (проверка распознавания статей затрат `>= 95 %`), **«Выгрузить проводки для 1С (CSV)»**.

6. **«Отчёты» (`/Reports`)**:
   - Доступны 3 финансовых отчёта: *План-факт исполнения бюджета*, *Договоры и контроль выданных авансов*, *Реестр заявок и нарушений лимитов*; печать/PDF и экспорт CSV (UTF-8 BOM).

### 4.3. Специалист по снабжению (`ProcurementSpecialist` / `supply`, WPF)

**Назначение роли:** договорная работа с поставщиками и субподрядчиками, импорт сметных данных и инициирование закупочных заявок.

**Что скрыто:** `Главная панель`, `Платёжный календарь`, `Риски и резерв P80`, блок зачёта авансов и банковских выписок, утверждение бюджетов и согласование/исполнение платежей.

#### Доступные разделы и управление

1. **«Договоры и выписки»** (открывается при входе):
   - **«Зарегистрировать договор»** — ввод проекта, номера договора, контрагента, УНП, суммы и спецификации.
   - **«Выполнить маппинг сметы»** — загрузка сметных строк CSV/XML и проверка процента сопоставления со справочником `CostItems`.
   - *На что влияет:* без зарегистрированного расходного договора (`SupplierSubcontractorOutgoing`) невозможно подать платёжную заявку или оформить акт С-2. Сумма договора также ограничивает максимально допустимые обязательства.

2. **«Платёжные заявки»**:
   - Просмотр статуса поданных заявок и карточки расчёта по выбранной строке.
   - **«Создать и проверить»** — создание заявки (`Текущий платёж` или `Новый аванс`) с привязкой к объекту, договору и статье затрат.
   - *На что влияет:* при создании заявки система автоматически проверяет **3 барьера**:
     1. свободный лимит $L_{\text{дост}} = B - O$: при превышении заявка автоматически становится **`Заблокирована`** (`Blocked`) и ждёт решения `CEO`;
     2. просроченный аванс по договору: при создании нового аванса по договору с просроченным старым авансом заявка блокируется правилом `AdvancePolicy`;
     3. прогноз кассового разрыва на дату платежа: выводится предупреждение с ближайшей безопасной датой.

### 4.4. Руководитель проекта / прораб (`ProjectManager` / `pm`, Web)

**Назначение роли:** работа на строительном объекте — просмотр лимитов и этапов **строго по тем проектам, на которые прораб назначен руководителем (`CEO`)**, оформление актов выполненных работ С-2 / справок С-3 с фотофиксацией, подача и доработка платёжных заявок.

**Что скрыто и заблокировано:** `Главная панель`, `Платёжный календарь`, `Риски и резерв P80`, `Договоры и выписки`, `Отчёты`, редактирование бюджетов/версий, а также **любые проекты, объекты, акты и заявки проектов, на которые данный прораб не назначен в `finance.ProjectAssignments`**.

#### Доступные разделы и управление

1. **«Проекты и бюджеты» (`/Projects`)** (открывается при входе):
   - **«Мои назначенные проекты и команда»** — перечень только своих проектов, сроков и ответственных лиц (если ни один проект ещё не назначен `CEO`, выводится уведомление с просьбой обратиться к руководителю организации).
   - **«Витрина свободного лимита `vFreeLimit`»** и **«Этапы работ по назначенным проектам (`PV / EV / AC`)»** — актуальный остаток $L_{\text{дост}}$ в разрезе объектов и статей затрат перед подачей новой заявки.

2. **«Акты С-2 (объект)» (`/Requests/Acts`)**:
   - Форма **«Оформление акта С-2 / справки С-3»**: выбор объекта (из назначенных проектов), договора, типа документа (`Акт С-2` или `Справка С-3`), номера, валовой суммы $S_{\text{акт}}$, зачёта аванса $A_{\text{зач}}$, удержания $U_{\text{удерж}}$, описания работ и путей к фотофиксации (`PhotoEvidencePaths`).
   - Кнопка **«Зарегистрировать акт»** (или **«Зафиксировать акт С-2»** на странице заявок):
     - *Что делает и на что влияет:* автоматически вычисляет сумму к оплате $S_{\text{к\_опл}} = S_{\text{акт}} - A_{\text{зач}} - U_{\text{удерж}}$, сохраняет документ в `finance.Documents` и формирует документальную базу для последующей оплаты выполненных работ.

3. **«Платёжные заявки» (`/Requests`)**:
   - Создание заявок (**«Создать и отправить на проверку»**) только по объектам назначенных проектов.
   - Для заявок в статусе **`Возвращена на доработку`** (`Returned`) доступна кнопка **«Отправить повторно»** (`Resubmit`) — повторно запускает проверки лимита/авансов и возвращает заявку финансовому менеджеру на согласование.

### 4.5. Бухгалтер (`Accountant` / `accountant`, WPF)

**Назначение роли:** фактическое проведение согласованных платежей, сверка банковских выписок с автоматическим закрытием исполненных платежей и дедупликацией по `BankOperationId`, зачёт авансов и выгрузка бухгалтерских проводок в 1С.

**Что скрыто:** `Главная панель`, `Платёжный календарь`, `Риски и резерв P80`, `Проекты и бюджеты`, создание договоров и согласование/одобрение заявок.

#### Доступные разделы и управление

1. **«Платёжные заявки»** (открывается при входе):
   - Просмотр заявок (фильтр по статусам, например `Согласована`), карточка выбранной заявки.
   - Поле номера платёжного поручения (`ПП-205`) и кнопка **«Исполнить платёж (Бухгалтер)»** (работает строго для заявок в статусе **`Согласована`**, `Approved`).
   - *На что влияет:*
     1. создаёт запись фактического платежа `Payment` в BYN по текущему курсу НБ РБ;
     2. переводит заявку в статус **`Исполнена`** (`Executed`);
     3. **увеличивает оплаченный факт $F$ (`PaidAmount`)** и **уменьшает остаток обязательства $O_{\text{ост}} = O - F$** в `finance.Obligations` (и в витрине `vFreeLimit`).

2. **«Договоры и выписки»**:
   - **«Контроль выданных авансов»** — ввод суммы и кнопка **«Зачесть аванс»** (уменьшает `Remainder`, пересчитывает процент использования $K_{\text{исп}}$; при полном зачёте закрывает аванс, снимая потенциальную блокировку новых авансов по договору).
   - **«Импорт банковской выписки CSV / MT940»** — вставка текста выписки и кнопка **«Загрузить и сверить выписку»**.
     - *На что влияет:* сопоставляет банковские операции по `PaymentRequestNumber`, закрывает исполненные заявки/платежи (`Closed` / `Reconciled`) и **отбрасывает дубли** по уникальному `BankOperationId` без повторного списания обязательств.
   - **«Выгрузить проводки для 1С (CSV)»** — формирует файл проводок `Дт 60 / Кт 51` в формате CSV (UTF-8 BOM) для импорта в 1С.

### 4.6. Специалист по рискам (`RiskSpecialist` / `risk`, Web)

**Назначение роли:** ведение реестра проектных рисков, оценка вероятности и денежного ущерба, построение матрицы $5\times 5$, расчёт портфельного резерва $P80$ по методу нормального приближения (СТБ ISO 31000-2020), анализ чувствительности $EAC$ и формирование профильного отчёта по рискам.

**Что скрыто:** `Главная панель`, `Проекты и бюджеты`, `Платёжные заявки`, `Платёжный календарь`, `Договоры и выписки` и финансовые отчёты.

#### Доступные разделы и управление

1. **«Риски и резерв P80» (`/Risks`)** (открывается при входе):
   - Выбор проекта и кнопка **«Показать проект»**.
   - **4 карточки итогов:** $\sum EMV$, СКО $\sigma$, **Резерв $P80$**, остаточный $EMV$ после мер реагирования.
   - **Матрица вероятности и влияния $5\times 5$** (цветовое зонирование по интегральному баллу $R = p_{\text{б}} \times I$ от 1 до 25).
   - **Реестр рисков проекта:** в каждой строке можно изменить вероятность `p` (например `0.35` или `0,35`), денежный ущерб `C`, остаточную вероятность после мер, комментарий и нажать **«Обновить»**.
   - **«Добавить риск в реестр»:** создание нового риска с кодом, описанием события, вероятностью, ущербом, владельцем, ранним индикатором и планом реагирования.
   - **Торнадо-анализ чувствительности $EAC$:** влияние ключевых риск-факторов на итоговую стоимость проекта.
   - *На что влияет:* при каждом обновлении или добавлении риска система автоматически пересчитывает $EMV_i$, $\sigma$, портфельный резерв $R_{P80}$ и фиксирует новую версию оценки (`RiskAssessment`) со снимком $P80$. **Эти величины напрямую меняют итоговый финансовый результат $R_{\text{фин}} = V - EAC - P80$ и KPI резерва на Главной панели `CEO`!** Если интегральный балл риска становится критическим, система публикует критическое уведомление.

2. **«Отчёты» (`/Reports`)**:
   - Доступен профильный отчёт **«1. Реестр рисков и расчёт резерва P80»**, печать/PDF и экспорт CSV (UTF-8 BOM).

**Что скрыто (НФТ-8):** по требованиям разделения полномочий администратор **не имеет доступа** ни к одному финансовому, договорному, проектному или рисковому разделу (не может создавать проекты, менять бюджеты, согласовывать или проводить заявки).

#### Доступные разделы и управление

2. **«Журнал аудита»**:

## 5. Сквозная карта взаимосвязей: что на что влияет в системе

Ниже приведена полная цепочка работы от пустой базы данных до закрытия платежа и расчёта финансового результата проекта:

1. **Создание учётных записей (`Admin`, WPF):**
   - `admin` создаёт сотрудников (в частности прораба `ProjectManager`, финансиста `FinancialManager`, снабженца `ProcurementSpecialist`, бухгалтера `Accountant`, риск-менеджера `RiskSpecialist`).
   - *Эффект:* пользователи появляются в кадровом списке для назначения на проекты (`CEO`) и получают доступ в свои клиенты.
2. **Запуск проекта и назначение прораба (`CEO`, WPF):**
   - `director` создаёт проект с начальным объектом, этапом и сразу выбирает **Руководителя проекта (прораба)** (или позже добавляет команду через `ProjectAssignments`). Одновременно создаётся бюджет `v1 (Draft)`.
   - *Эффект:* только выбранный прораб начинает видеть этот проект, его объекты, лимиты, заявки и акты в Веб-клиенте.
3. **Наполнение и утверждение бюджета (`FinancialManager` Web / `CEO` WPF → утверждает только `CEO` WPF):**
   - Лимиты добавляются/корректируются в `Draft`-версии; `CEO` нажимает **«Утвердить выбранную Draft-версию»**.
   - *Эффект:* задаётся $BAC$ и плановый бюджет $B$ по каждой паре *(Объект × Статья)* в `finance.vFreeLimit`. Пока бюджет не утверждён, $B = 0$ и все заявки блокируются как перерасход.
4. **Договоры (`ProcurementSpecialist` WPF / `FinancialManager` Web):**
   - Регистрируется договор с поставщиком/субподрядчиком и при необходимости загружается смета.
   - *Эффект:* договор становится доступен в формах актов С-2 и платёжных заявок.
5. **Акты С-2/С-3 на площадке и подача заявок (`ProjectManager` Web / `ProcurementSpecialist` WPF):**
   - Прораб оформляет акт С-2 с фотофиксацией и подаёт платёжную заявку.
   - *Эффект:* система сверяет остаток лимита $L_{\text{дост}} = B - O$, проверяет просроченные авансы и кассовые разрывы:
     - если лимит превышен или есть просроченный аванс → заявка получает статус **`Blocked`** и попадает к **`CEO`** (`UC04`);
     - если лимит соблюдён → заявка получает статус **`PendingApproval`** и попадает к **`FinancialManager` / `CEO`**.
6. **Согласование перерасхода (`CEO`, WPF) и финансовое визирование с ЭЦП (`FinancialManager` Web / `CEO` WPF):**
   - При положительном решении `CEO` по перерасходу заявка разблокируется и поступает на ЭЦП.
   - При нажатии **«Согласовать (ЭЦП)»** заявка переходит в **`Approved`** и **списывает обязательство $O$** (свободный лимит $L_{\text{дост}} = B - O$ уменьшается немедленно, предотвращая повторный расход теми же средствами; заявки в проверке $Q$ показаны справочно и повторно не вычитаются).
7. **Балансировка платёжного календаря (`FinancialManager` Web / `CEO` WPF):**
   - Если согласованная заявка или позиция графика создаёт кассовый разрыв ($C(t) < C_{\min}$), финансист сдвигает дату платежа в **Платёжном календаре** — разрыв на графике исчезает сразу.
8. **Оплата и банковская выписка (`Accountant`, WPF):**
   - Бухгалтер проводит платёж (**«Исполнить платёж»**) → заявка становится **`Executed`**, растёт оплаченный факт $F$, уменьшается остаток долга $O_{\text{ост}} = O - F$ и формируется проводка для 1С.
   - При загрузке выписки CSV/MT940 подтверждённые банком платежи переводятся в статус **`Closed` / `Reconciled`** с защитой от дублей по `BankOperationId`.
9. **Мониторинг рисков (`RiskSpecialist`, Web):**
   - Изменение вероятности $p$ или ущерба $C$ обновляет матрицу $5\times 5$, $EMV$, $\sigma$ и резерв $P80$, что сразу отражается на прогнозе чистого финансового результата проекта $R_{\text{фин}}$ у **`CEO`**.

## 6. Математические формулы и контрольные примеры (глава 1)

1. **Свободный лимит бюджета (без двойного списания заявок $Q$):**
   $$L_{\text{дост}} = B - O, \qquad O_{\text{ост}} = O - F$$
   - `PRJ-2026-01` / `ST-01`: $B = 10\,000$, $O = 6\,000$, $F = 3\,000$, $Q = 1\,000 \Rightarrow L_{\text{дост}} = 4\,000$, $O_{\text{ост}} = 3\,000$.
   - `PRJ-2026-02` / `ST-02`: $B = 10\,000$, $O = 10\,500 \Rightarrow L_{\text{дост}} = -500$ (автоблокировка заявки с перерасходом).
2. **Сумма к оплате по акту С-2 / справке С-3:**
   $$S_{\text{к\_опл}} = S_{\text{акт}} - A_{\text{зач}} - U_{\text{удерж}}$$
3. **Прогноз стоимости по освоенному объёму (EVM):**
   $$CPI = \frac{EV}{AC}, \qquad SPI = \frac{EV}{PV}, \qquad EAC = AC + \frac{BAC - EV}{CPI}$$
   - `PRJ-2026-01`: $EV = 3\,000$, $AC = 3\,300$, $PV = 3\,400$, $BAC = 11\,000 \Rightarrow CPI \approx 0{,}909$, $SPI \approx 0{,}882$, $EAC = 12\,100$.
4. **Платёжный календарь и кассовые разрывы (5 / 30 / 90 дней):**
   $$C(t) = C(t-1) + P(t) - V(t), \qquad \text{Разрыв}(t) = \max\bigl(0,\ C_{\min} - C(t)\bigr)$$
5. **Оценка рисков, матрица $5\times 5$ и резерв $P80$ ($z = 0{,}84$, СТБ ISO 31000-2020):**
   $$EMV_i = p_i \cdot C_i, \qquad \sigma = \sqrt{\sum p_i (1 - p_i) C_i^2}, \qquad R_{P80} = \sum EMV_i + 0{,}84 \cdot \sigma$$
   - Для 12 рисков проекта `PRJ-2026-01`: $\sum EMV = 1\,340{,}00$, $\sigma = 723{,}22$, $R_{P80} = 1\,947{,}51$ тыс. р. (округлённо $1\,948$), остаточный $\sum EMV_{\text{ост}} = 715{,}00$ тыс. р.

## 7. Запуск и тестирование

### Запуск в Visual Studio 2022 (17.12+ с .NET 9 SDK)
1. Убедитесь, что **MS SQL Server** запущен, и при необходимости скорректируйте `ConnectionStrings:DefaultConnection` в `src/FinanveManager.Web/appsettings.json` и `src/FinanveManager.WpfClient/appsettings.json`.
2. *(Необязательно)* Предварительно разверните схему и демо-данные через SSMS (`database/01_schemas_and_tables.sql`, затем `database/02_seed_data.sql`). Если этого не делать, приложения создадут пустую БД `FinanveManagerDb` автоматически при первом старте и предложат инициализацию на экране входа.
3. Откройте `Finanve_manager_and_risk_analyst.sln`:
   - **Веб-клиент (`FinanveManager.Web`):** назначьте стартовым проектом и нажмите **F5** (`https://localhost:5051` или `http://localhost:5050`).
   - **Настольный клиент (`FinanveManager.WpfClient`):** назначьте стартовым проектом и нажмите **F5**.
   - Оба клиента подключаются к одной базе данных и могут работать одновременно (например, `CEO` в WPF и `ProjectManager` / `FinancialManager` в браузере).

### Сборка и запуск модульных тестов из командной строки
```powershell
dotnet restore Finanve_manager_and_risk_analyst.sln
dotnet build Finanve_manager_and_risk_analyst.sln -c Release
dotnet test tests/FinanveManager.Tests/FinanveManager.Tests.csproj
```

> **Примечание по NuGet (`.NET 9.0`):** пакеты `Microsoft.EntityFrameworkCore.SqlServer` и `Microsoft.EntityFrameworkCore.InMemory` в `FinanveManager.Data.csproj` закреплены на версии **`9.0.0`** (совместимой с `net9.0`). Не повышайте их до `10.x`/`11.x` без миграции целевого фреймворка.
